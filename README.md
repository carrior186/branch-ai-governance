# 光华管理学院本科生党支部 AI 协作规范与实践体系

> 项目暂名：`branch-ai-governance`  
> 当前阶段：内容填充第一阶段（讨论与试用，不代表正式制度）

本项目用于逐步形成一套可维护、可复核、未来可公开的党支部 AI 协作体系。它以总则为共同基础，以岗位与任务领域的指南为扩展，以经脱敏和审核的案例沉淀经验，并通过一个工作流引导型 Skill 帮助使用者在具体任务中正确查阅和应用这些材料。

## 信息安全边界

本仓库只用于管理可讨论、可审查、原则上可公开的规范与方法，不承担支部日常真实工作资料的存储职责。不得提交：

- 党员、申请人、联系人或活动参与者的个人信息；
- 内部会议原始记录、未公开组织安排、账号凭据或权限信息；
- 需要保密、限制传播或尚未完成公开审查的材料；
- 能通过组合信息识别个人、组织关系或内部决策过程的内容。

不确定能否进入仓库时，默认不提交，先由相应负责人进行人工判断。Git 历史不会因普通删除而自动消除，因此敏感信息不得以“先上传、以后再删”的方式处理。

## 如何使用

1. 先阅读总则 v0.1，确认当前材料仍为讨论稿，并检查任务的信息边界。
2. 按任务的主要责任领域查阅一个或多个分则。
3. 复杂任务可先使用总则附录中的“最小任务卡”，确定目标、人机分工和最终验收人。
4. 在 Codex 中调用 `branch-assistant`，或直接要求其“按照本项目规范协助完成某项任务”。
5. 对事实、程序、对外发布内容及重大修改进行人工核验和批准。
6. 将可复用经验先记录为修改建议；只有完成脱敏与审核后，才考虑形成案例。

## 维护责任

- 副书记负责牵头维护总则、协调跨领域一致性和版本发布；书记参与重大事项审定。
- 各领域负责人维护对应分则；活动统筹指南由承担活动组织职责的人员提出改进建议，并由指定负责人归口审核。
- AI 可以协助起草、比对、检查和整理，但不能替代责任主体批准正式规范。
- 涉及基本原则、责任边界、保密要求、正式流程或对外公开范围的变更，必须经过人工重大变更审核。

完整维护规则见[项目建设说明](docs/项目建设说明.md)。

## 当前不做的事

- 不宣称本项目材料已获正式批准；
- 不在内容尚未成熟时建立大量空目录、自动化流程或独立 Skill；
- 不收集真实业务数据来“训练”或测试流程；
- 不自动发布 GitHub 仓库，也不自动授权任何外部服务。
